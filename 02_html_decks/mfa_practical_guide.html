📊 MFAが必須な理由 — データと事例で説得する

「パスワードだけでは守れない」を数字で示す

Microsoftのセキュリティレポートによると、MFAを有効にするだけでアカウント侵害リスクを99.9%低減できる。パスワードは漏洩前提で設計するのが現代のセキュリティ基本原則だ。

  • Have I Been Pwned（haveibeenpwned.com）登録データ: 130億件超のパスワード漏洩記録
  • 日本でも毎年数百万件のビジネスメールとパスワードがダークウェブで流通

🔐 MFA方式比較（詳細）

🥇 FIDO2 / パスキー（最推奨） フィッシング耐性: 完全

セキュリティ強度: ★★★★★

強み:
  • デバイスに紐付いた秘密鍵でフィッシングサイトでは機能しない
  • パスワードレス認証が可能（YubiKey・Windows Hello）
  • 最高のセキュリティ強度と優れたUX
注意点:
  • デバイス紛失時の復旧フロー設計が必要
  • 全社展開には時間とデバイス調達コストがかかる
  • 推奨製品: YubiKey、Windows Hello for Business、Google Passkey
🥈 アプリ プッシュ通知（Microsoft Authenticator等） 番号照合必須

セキュリティ強度: ★★★★☆（番号照合あり）

強み:
  • スマートフォンのみで実装可能（追加コスト最小）
  • UXが良い（承認ボタン1タップ）
  • Microsoft Entra ID・Okta・Duoと深く統合
注意点:
  • 番号照合（Number Matching）を必ず有効化（MFA疲労攻撃対策）
  • スマートフォン紛失時の対応フロー必要
  • プッシュ通知なしの地域・環境への対応検討
🥉 TOTP（Google Authenticator / Microsoft Authenticator） 標準的な選択

セキュリティ強度: ★★★☆☆

強み:
  • オフラインでも機能（ネットワーク不要）
  • 対応アプリが豊富（認証器選択の自由度が高い）
  • リアルタイム通信不要で安定性が高い
注意点:
  • フィッシングサイトでOTPを入力させる攻撃（AiTM）に対して脆弱
  • 6桁数字入力のUXがプッシュより劣る
  • 旧式だが既存システムとの互換性が高い
⚠️ SMS OTP（非推奨） 段階的廃止推奨

セキュリティ強度: ★☆☆☆☆

  • スマートフォン不要（ガラケー/フィーチャーフォンでも可）
  • 追加アプリ不要で導入障壁が低い

📅 段階的導入計画（3フェーズ）

「管理者から始めて全社員・外部委託先へ」の展開ロードマップ

🚨 Phase 1（〜1ヶ月）: IT管理者・特権アカウント全員にMFA必須

対象アカウント

  • Active Directoryのドメイン管理者・Enterprise Admins
  • Azure/M365のグローバル管理者・Exchange管理者
  • IT担当者・システム管理者全員
  • PAMシステム管理アカウント
  • クラウドインフラ（AWS/Azure/GCP）の管理者

推奨MFA方式

  • 第一選択: FIDO2（YubiKey等）またはWindows Hello for Business
  • 代替: Microsoft Authenticator（番号照合必須）

実装タスク

  • Entra ID条件付きアクセスポリシー作成（管理者グループ→MFA必須）
  • Microsoft Authenticatorの番号照合（Number Matching）有効化
  • 管理者向け展開説明会・ヘルプデスク体制整備
  • 緊急連絡用のバックアップ認証手段の登録（物理キー等）
期待効果: 最もリスクの高い特権アカウントを即座に保護。AD侵害・クラウド管理者乗っ取りリスクを大幅低減。
⚡ Phase 2（〜6ヶ月）: 全社員へのMFA展開

対象アカウント

  • 全社員（正社員・嘱託・パートタイム）
  • Microsoft 365・Entra IDアカウント保有者
  • SaaS（Salesforce・Slack・Zoom等）利用者

展開方針

  • 本社→支社→工場・店舗の順で段階展開
  • Microsoft Authenticatorアプリ配布・登録ガイド作成
  • ヘルプデスクへのMFA関連問い合わせ対応訓練
  • 例外処理フロー（海外出張・スマートフォン紛失時）の整備

実装タスク

  • Entra IDのセキュリティデフォルト or 条件付きアクセスでMFA必須化
  • MFA登録キャンペーン（ユーザー向け案内メール・ポスター）
  • 認証アプリのセルフサービス登録ポータル設定
  • SMS MFAからアプリMFAへの移行通知（3ヶ月猶予）
注意: 全社一斉展開はヘルプデスクに過大な負荷をかける。部門別・拠点別の段階展開と十分な事前周知が必須。
✅ Phase 3（〜12ヶ月）: 外部委託先・FIDO2移行・条件付きアクセス強化

対象アカウント

  • 協力会社・外部委託先SE
  • SIer・ベンダー（VPN・リモートアクセス利用者）
  • Phase 2のSMS MFA利用者（アプリMFAへ移行）

FIDO2移行対象

  • 特権アカウント（Phase 1の継続強化）
  • 経営層・役員アカウント
  • 財務・人事等の機密データ取扱者

実装タスク

  • 外部委託先向けMFA登録フロー（Entra B2B Guest / External ID）
  • 特権ユーザー向けYubiKey配布・Windows Hello for Business展開
  • 条件付きアクセス強化: 登録済みデバイス+MFA+リスク評価
  • 継続的アクセス評価（CAE）の有効化
  • UEBA（異常認証検知）の本格運用開始
最終形: 全社員・全委託先がMFA適用済み。特権ユーザーはFIDO2対応。条件付きアクセスでリスクベース認証が稼働。

⚠️ MFA疲労攻撃（MFA Fatigue / Prompt Bombing）への対応

事例: 2022年Uber・Okta・Cisco侵害事件では「MFA疲労攻撃」が悪用された。攻撃者は盗んだパスワードでログイン試行を繰り返し、深夜や休日に大量のMFAプッシュ通知を送り続け、ユーザーが誤って「承認」するのを待った。

対策1: 番号照合（Number Matching）の必須化

承認画面に2〜3桁の数字が表示され、ユーザーがその数字をスマートフォンに入力して初めて承認できる仕組み。攻撃者がプッシュを送っても画面を見ていないユーザーは承認できない。

設定方法（Entra ID）:
Entra管理センター → 認証方法 → Microsoft Authenticator → 番号照合: 有効

効果: MFA疲労攻撃の成功率を大幅に低減。2023年以降、Microsoftはデフォルト有効化を推奨。

対策2: FIDO2/パスキーへの移行

FIDO2認証は物理デバイスまたはデバイス内蔵の認証器を使い、フィッシングサイトや偽のMFAプッシュでは機能しない設計。MFA疲労攻撃そのものが成立しない。

対策3: 条件付きアクセス強化

  • 未登録デバイスからのアクセスを自動ブロック
  • リスクの高いサインイン（異常な場所・速度）を即時ブロック
  • 継続的アクセス評価（CAE）: セッション中もリスク監視

🔧 製品別実装ガイド — Entra MFA / Okta / Cisco Duo

各製品の設定ポイントとベストプラクティス

Microsoft Entra MFA（旧Azure MFA）

ライセンス: Entra Free（制限あり）/ P1（条件付きアクセス）/ P2（Identity Protection含む）

必須設定項目

1. 番号照合の有効化 Entra管理センター → 保護 → 認証方法 → Microsoft Authenticator → 番号照合: 有効化
2. 条件付きアクセスポリシー 特権ロール: MFA必須 / 全ユーザー: 登録済みデバイス+MFA / リスク高: ブロック
3. Identity Protection（P2） サインインリスクポリシー: リスク「高」→ MFA要求 / ユーザーリスク: リスク「高」→ パスワード変更要求
4. 登録キャンペーン Entra管理センター → セキュリティ → 認証方法 → 登録キャンペーン: 有効化（14日間の猶予付き）

Okta Adaptive MFA

特徴: リスクベース認証・多様な認証器・AD/LDAPとの深い統合

推奨設定ポイント

1. サインオンポリシー アプリごとに「条件」（ネットワーク・デバイス状態・グループ）と「アクション」（MFA要求レベル）を設定
2. Okta ThreatInsight ブルートフォース攻撃・パスワードスプレーを自動検知してブロック。無償で利用可能。
3. Device Trust Okta管理登録デバイスのみに認証を許可。MDM（Jamf/Intune）との統合でデバイス証明書確認。

AD統合のポイント

  • Okta AD Agentをオンプレミスに展開してADと双方向同期
  • ADユーザー属性（部署・役職）をOktaポリシーで活用可能
  • OktaがIdP、ADがユーザーディレクトリとして共存するパターンが日本市場で一般的
  • Universal Directory でAD・HR系・クラウドの属性を統合

Cisco Duo Security

特徴: エージェントレス展開・既存VPN/RDPへの素早い統合・中堅企業向け

Duoの強み

  • 既存インフラへの素早い統合: VPN（Cisco ASA/Palo Alto/Fortinet）・RDP・SSH・OWAへのMFA追加がエージェント方式で短期間導入可能
  • ダッシュボードの見やすさ: デバイス健全性・不審なログインを一目で確認
  • Duo Verified Push: 番号照合機能（MFA疲労攻撃対策）

典型的な導入パターン

  • 既存SSL-VPN（Cisco ASA/Juniper）へのMFA追加（1〜2週間で導入可能）
  • RDP/Windowsログインへのセカンダリ認証として追加
  • Entra ID/Oktaと並行運用（Duoをセカンドファクタ専用に使う）
  • 将来的にEntra ID P2に統合移行する際の中間策としても有効

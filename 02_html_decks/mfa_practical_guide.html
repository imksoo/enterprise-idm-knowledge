📊 MFAが必須な理由 — データと事例で説得する

「パスワードだけでは守れない」を数字で示す
Microsoft社の調査: MFAを有効にするだけで、アカウント乗っ取り攻撃の 99.9% を防げる（2019年調査）。パスワード漏洩が起きても、MFAがあれば被害を防止できる。

パスワード漏洩統計

  • Have I Been Pwned (HIBP): 2024年時点で 120億件超のアカウント情報がダークウェブで流通
  • Verizon DBIR 2023: データ侵害の原因の 74% が認証情報の窃取・人的要因
  • IBM Cost of Data Breach 2023: 日本企業のデータ侵害平均損失 4.45億円
  • Ponemon Institute: パスワードの再利用率は 65%（1つ漏れると複数サービスが危険）

日本企業での被害事例

2022年 トヨタ自動車系サプライヤー: VPNアカウントへの不正アクセスから工場停止。生産ライン1日停止で約1,500億円相当の損失影響。
2023年 大手金融機関: 業務委託先従業員のパスワードが漏洩。顧客情報数万件が流出。インシデント対応・通知コストだけで数億円。

📅 段階的導入計画（3フェーズ）

管理者から始め、全社員、外部委託先へと段階的に展開する現実的なロードマップ
Phase 1 〜3ヶ月: IT管理者・特権アカウント全員にMFA必須 最優先

実施内容

  • ドメイン管理者・グローバル管理者・セキュリティ管理者にMFA強制適用
  • 条件付きアクセスポリシーの基本設定（管理者ロール全員MFA必須）
  • ブレークグラス緊急アカウント（2件）の設定とMFA除外
  • Microsoft Authenticatorの番号照合（Number Matching）有効化
  • MFAヘルプデスク体制の準備（登録支援・リセット対応）

成功指標

目標: 管理者アカウント MFA適用率 100%
測定方法: Entra ID サインインログ / MFA登録状況レポート
リスク: 管理者が登録できない場合の業務停止対策を事前に準備

除外グループの設計

  • ブレークグラスアカウント（場所条件でのみアクセス許可）
  • サービスアカウント（CA除外グループに追加）
  • MFA非対応レガシーシステム（専用除外ポリシー）
Phase 2 〜6ヶ月: 全社員にMFA展開 高優先

実施内容

  • 全社員へMFA登録を段階的に展開（部門別ロールアウト）
  • Microsoft Authenticatorプッシュ通知＋番号照合を標準に設定
  • 事前周知（メール・イントラ通知）とヘルプデスク強化
  • 除外グループの段階的縮小（登録率90%達成後に縮小）
  • MFA登録レポートを週次で経営報告

⚠️ MFA疲労攻撃（MFA Fatigue / Prompt Bombing）への対応

🚨 実際の侵害事例: 2022年Uber侵害 — 18歳のハッカーが盗んだパスワードで深夜に大量のMFAプッシュを送信。ドライバーになりすましてWhatsAppで連絡「ITです、承認してください」と社会工学を組み合わせ、従業員が誤承認。内部ネットワーク全体に侵入。同年、Okta・Cisco等でも同様の手口が使われた。

対策1: 番号照合（Number Matching）

承認画面の2〜3桁の数字をスマートフォンに入力しないと承認できない。攻撃者が画面を見ていなければ攻撃不可。Entra ID・Okta・Duoで設定可能。

2023年以降、Microsoftはデフォルト有効化を推奨

対策2: FIDO2/パスキー移行

MFA疲労攻撃の根本的な解決策。物理デバイスが必要なため、プッシュ通知攻撃自体が成立しない。フィッシング耐性も同時に獲得できる。

Windows Hello for Business + YubiKey の組み合わせが有効

対策3: UEBA・異常検知

短時間に多数のMFAリクエストが発生した際にアラート。Entra ID Protection（P2）のリスクポリシーや SIEM のカスタムルールで検知。

検知だけでは不十分。必ず番号照合またはFIDO2と組み合わせる

PowerShell: 番号照合の有効化

# Microsoft Authenticator 番号照合の有効化（Microsoft Graph PowerShell）
Install-Module -Name Microsoft.Graph.Identity.SignIns -Force
Connect-MgGraph -Scopes "Policy.ReadWrite.AuthenticationMethod"

# 番号照合の設定を有効化
$body = @{
    "@odata.type" = "#microsoft.graph.microsoftAuthenticatorAuthenticationMethodConfiguration"
    state = "enabled"
    featureSettings = @{
        numberMatchingRequiredState = @{
            state = "enabled"
        }
        displayAppInformationRequiredState = @{
            state = "enabled"  # 追加コンテキスト（アプリ名表示）
        }
    }
}

Update-MgPolicyAuthenticationMethodPolicyAuthenticationMethodConfiguration `
    -AuthenticationMethodConfigurationId "MicrosoftAuthenticator" `
    -BodyParameter $body

Write-Host "番号照合を有効化しました" -ForegroundColor Green

PowerShell: MFA未登録ユーザーの一覧取得

# MFA未登録ユーザーをCSVにエクスポート
Connect-MgGraph -Scopes "UserAuthenticationMethod.Read.All","User.Read.All"

$users = Get-MgUser -All -Filter "accountEnabled eq true" `
    -Property "Id,DisplayName,UserPrincipalName,Department"

$results = foreach ($user in $users) {
    $methods = Get-MgUserAuthenticationMethod -UserId $user.Id
    $hasMFA = $methods | Where-Object {
        $_.AdditionalProperties["@odata.type"] -ne
        "#microsoft.graph.passwordAuthenticationMethod"
    }
    [PSCustomObject]@{
        DisplayName       = $user.DisplayName
        UPN               = $user.UserPrincipalName
        Department        = $user.Department
        MFARegistered     = if ($hasMFA) { "登録済" } else { "未登録" }
        MethodCount       = $methods.Count - 1  # パスワード除く
    }
}

$results | Where-Object { $_.MFARegistered -eq "未登録" } |
    Export-Csv -Path ".\mfa_not_registered_$(Get-Date -Format yyyyMMdd).csv" `
    -Encoding UTF8 -NoTypeInformation
Write-Host "MFA未登録: $(($results | Where-Object {$_.MFARegistered -eq '未登録'}).Count) 名"

ライセンス: Okta Workforce Identity Cloud（MFA Adaptive含む）

ポリシー設定ベストプラクティス

① 認証ポリシー（Authentication Policy） アプリケーション単位でMFA要件を設定。高セキュリティアプリ（財務・HR等）にはFIDO2を必須化

③ 登録ポリシー 新規ユーザーのMFA登録を初回ログイン時に強制。猶予期間を0日に設定（セキュリティ重視の場合）

🏗️ ゼロトラストアーキテクチャ構成要素
コンポーネント役割主要製品
IdP（Identity Provider）認証・認可の起点。全アクセスはここを通すEntra ID, Okta, Ping Identity
条件付きアクセス（CA）ユーザー・デバイス・場所・リスクスコアで動的にアクセス制御Entra CA, Okta Policy Engine
MDM/EDRデバイスの健全性をアクセス条件に組み込むIntune, CrowdStrike, SentinelOne
SASE/SSEクラウドエッジでのネットワークセキュリティ統合Zscaler, Netskope, Prisma Access
マイクロセグメンテーション東西通信の制御（サーバー間の不正移動防止）Illumio, Guardicore
PAM特権アクセスのゼロトラスト化（JIT+記録）CyberArk, BeyondTrust
SIEM/SOAR全ログ統合分析・自動対応Microsoft Sentinel, Splunk, IBM QRadar
⚙️ 日本企業でよくある実装パターン

パターンA: Microsoft中心（M365導入済み企業向け）

Entra ID P2 → 条件付きアクセス → Intune → Microsoft Defender for Endpoint → Microsoft Sentinel。追加費用を最小化しつつゼロトラストを段階導入。M365 E5で大部分をカバー可能。

パターンB: マルチベンダー（セキュリティ最優先）

Okta（IdP） + CrowdStrike（EDR） + Zscaler（SASE） + CyberArk（PAM） + Splunk（SIEM）。Best-of-breed構成。金融・製薬など高セキュリティ要件の企業向け。統合コストが高い。

パターンC: ハイブリッド移行期（オンプレ残存）

Entra Hybrid Join + ADFS → 段階的にEntra ID直接認証へ移行。オンプレサーバーはPAM経由アクセス。Azure VPN/ExpressRoute経由でオンプレ接続を維持しながら段階移行。

🔗 ID管理との統合ポイント（ZT × IDM）
  • 条件付きアクセスにIGA連携：IGA（SailPoint等）で承認されたロールのみCA許可
  • リスクベース認証：Entra ID Protectionのリスクスコアで自動的にMFAを要求
  • デバイスコンプライアンス確認：Intuneパッチ未適用デバイスはアクセス拒否
  • 継続的アクセス評価（CAE）：セッション中でもリスク上昇を検知し即座に再認証
  • SIEMへの全ログ統合：IdP・MDM・PAM・SASE全ての認証ログをSIEMに集約

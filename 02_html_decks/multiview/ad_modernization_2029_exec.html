決断 1: Device Writeback の扱い

Device Writeback は一部シナリオでは有用だが、全社標準として必須ではない。目的が曖昧なまま有効化すると、Active Directory 側の設計複雑性だけが増える。必要機能を明示し、不要なら採用しない判断が妥当である。

決断 2: PTA の評価

Pass-through Authentication は認証判定をオンプレミスに残せるため、一部統制要件には適合しやすい。一方で、エージェント可用性、ネットワーク経路、障害時の依存関係が増える。明確な要件がない限り、PHS より優先する理由は弱い。

決断 3: Federation の評価

Federation は高度な制御や既存投資活用を理由に残ることがあるが、Active Directory Federation Services の可用性設計、証明書、プロキシ、障害時対応は重い。新規導入の第一選択にはしにくく、既存運用がある場合も縮退計画を持つべきである。

Seamless SSO の使いどころ

Seamless SSO は社内ネットワークやドメイン参加端末を前提にユーザー体験を改善するが、ゼロトラストそのものではない。PHS と組み合わせて SaaS サインインの摩擦を減らす用途には有効だが、認証強化の主役は Conditional Access と MFA である。

❓ 経営層からよくある質問 Q&A
「なぜ今このタイミングで？」
Windows Server 2012/2016のサポート終了（2023〜2027年）と2029年問題が重なる「移行の最終機会」です。放置するほどリスクと移行コストが増大します。
「クラウドに移行すれば安全になるのか？」
クラウドは手段であり、ID管理の設計が不適切なら従来と同じリスクが残ります。重要なのは「誰が何にアクセスできるか」を正しく制御することです。
「既存ベンダーに任せればよいのでは？」
ID管理は全システムの「鍵管理」です。特定ベンダー依存は長期リスクになります。オープン標準ベースの設計で依存度を下げることが重要です。
「何から始めればよいか？」
まず「特権アカウントの棚卸し」と「退職者アカウントの確認」から着手できます。コストゼロで高リスクを即座に可視化できます。
「セキュリティ投資は費用対効果が見えにくいのでは？」
インシデント発生時のコスト（復旧・賠償・信頼毀損）と比較すれば定量化できます。保険料と同じ発想で、「発生確率×損失額」で評価することを推奨します。

🔍 コンプライアンス観点での技術要件

Windows LAPS と旧 Microsoft LAPS の違い

Windows LAPS は OS 標準機能として統合され、AD と Entra ID の両保存先、パスフレーズ、ポスト認証アクション、旧ポリシー互換性を備える。一方で旧 Microsoft LAPS は AD 中心の追加導入型であり、今から新規採用する優先度は低い。

LAPS の設計要点

共有ローカル管理者パスワードを残すと端末 1 台侵害から全域横展開につながる。LAPS では端末ごとに異なる秘密情報、短めのローテーション、閲覧権限の最小化、回収後の利用停止確認を組み合わせるべきである。

JEA の価値

フル管理者権限を配らず、特定業務に必要な PowerShell コマンドだけを許可できる。日本企業でよくある運用委託先への広い管理者権限付与を縮小するうえで有効である。

📋 知識ベース由来のコンプライアンス要件

Windows LAPS と旧 Microsoft LAPS の違い

Windows LAPS は OS 標準機能として統合され、AD と Entra ID の両保存先、パスフレーズ、ポスト認証アクション、旧ポリシー互換性を備える。一方で旧 Microsoft LAPS は AD 中心の追加導入型であり、今から新規採用する優先度は低い。

LAPS の設計要点

共有ローカル管理者パスワードを残すと端末 1 台侵害から全域横展開につながる。LAPS では端末ごとに異なる秘密情報、短めのローテーション、閲覧権限の最小化、回収後の利用停止確認を組み合わせるべきである。

JEA の価値

フル管理者権限を配らず、特定業務に必要な PowerShell コマンドだけを許可できる。日本企業でよくある運用委託先への広い管理者権限付与を縮小するうえで有効である。

JEA 導入時の落とし穴

ロール設計が曖昧だと結局フル PowerShell を許可しやすい。許可コマンド、引数、外部実行、モジュール更新影響を明示し、トランスクリプションと SIEM 連携まで設計して初めて監査可能な最小権限になる。

Entra ID PIM の使いどころ

クラウド管理ロール、Privileged Access Group、Azure リソース管理の常時権限を避ける中核機能として用いる。MFA、承認、理由入力、時間制限、通知を標準化し、恒久的な active assignment を例外化するべきである。

JIT アクセスパターン

JIT は単に時間制限を付けるだけでは不十分である。チケット番号、対象システム、作業窓、承認者、操作ログ、作業後レビューを一連でつなぐと、内部不正と侵害後の権限悪用の両方を抑制できる。

PAW の実務的な位置づけ

PAW は上級管理者だけの専用端末ではなく、Tier 0 管理と一般業務を混在させないための基本制御である。メール添付や一般 Web 閲覧を行う端末から Tier 0 へ接続させないことが侵害耐性を大きく左右する。

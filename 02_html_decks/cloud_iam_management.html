🚨 マルチクラウドIAMの典型的問題

「誰が何にアクセスできるか分からない」症候群

AWS・Azure・GCPそれぞれにIAMが存在し、開発・本番・ステージング環境が混在。気づいたら2000人超のIAMユーザーが存在し、誰が何の権限を持っているか把握不能になる。「Administrator権限を持ったまま退職者」のアカウントが残存するケースも多発。

問題パターン発生頻度リスク
過剰権限付与（Administrator多用）非常に多い侵害時の被害最大化
未使用・孤立IAMアカウント多い休眠アカウント悪用
アクセスキー長期使用（ローテーションなし）多いキー漏洩→不正アクセス
S3/BlobのPublicアクセス設定ミス中程度データ漏洩
マルチクラウド間で権限の不統一多いガバナンス不全

🔍 CIEM（クラウドIAM権限管理）とは

CIEM = Cloud Infrastructure Entitlement Management

マルチクラウド環境の全IAM権限を可視化し、実際に使われていない権限を自動検出・最小化を提案するツール。AWS/Azure/GCPすべてのIAM設定を1画面で把握できます。

🏗️ マルチクラウドIAM統一アーキテクチャ（推奨）

Entra IDをハブとして全クラウドを統合する構成

Entra ID → AWS SSO（IAM Identity Center）/ Azure RBAC / GCP Workload Identity Federation の3方向に連携。人間のログインは全てEntra IDのMFA+条件付きアクセスを通過。クラウドのIAMロールはEntra IDのグループとマッピング。

統合ポイント設定メリット
Entra ID → AWSAWS IAM Identity Center + SAML/OIDC1か所でAWSアクセス管理
Entra ID → AzureEntra ID自身（Azure AD = Entra ID）PIM・条件付きアクセス統合
Entra ID → GCPWorkload Identity Federationサービスアカウントキー不要
SIEM統合CloudTrail/ActivityLog/Audit Logを全部Microsoft Sentinelに集約マルチクラウドのログを一元分析

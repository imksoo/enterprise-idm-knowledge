1. 導入・目的説明

このチェックリストは情報システム部門が自社の Active Directory / ID管理の現状を自己診断するためのツールです。5領域25問に回答することで現状スコアを算出し、優先的に対処すべき課題を特定できます。診断会議・経営報告・監査対応資料としてご活用ください。

📋 このチェックリストの使い方

各設問に対して以下3段階で回答してください：

  • ○ 対応済み　4点
  • △ 一部対応　2点
  • × 未対応　0点

25問 × 最大4点 = 100点満点

🎯 活用シーン

  • 情報セキュリティ委員会での現状報告
  • 経営層・取締役会向けのリスクレポート
  • 外部監査・ISO 27001 審査前の事前点検
  • ISMS・Pマーク・SOC2 対応の証跡収集
  • SIer への改善提案・RFP 作成のベースライン
  • 年次セキュリティレビューの定点観測
注意: このチェックリストは一般的なベストプラクティスに基づいており、法的義務や規制要件を保証するものではありません。FISC安全対策基準・金融庁ガイドライン・個人情報保護法等の個別要件については専門家にご相談ください。

① 認証管理（Authentication）最大20点

パスワードポリシー・MFA・条件付きアクセス等の認証強度を評価します

Q1. 全社員のパスワードは8文字以上・複雑性要件（英大小文字・数字・記号）が Active Directory のグループポリシー（Fine-Grained Password Policy 含む）で設定されているか
確認場所: GPO → コンピューターの構成 → Windowsの設定 → セキュリティの設定 → アカウントポリシー
—
Q2. IT管理者・特権アカウント（Domain Admins 等）の全員に多要素認証（MFA）が適用されているか
確認方法: Entra ID（Azure AD）条件付きアクセス / Azure MFA / 物理トークン等の適用状況確認
—
Q3. 一般社員にもMFAが展開されているか（全社員の50%以上をカバー）
Microsoft Authenticator / Google Authenticator / TOTP / SMS認証等を含む。Entra ID P1 以上のライセンスで条件付きアクセスが利用可能
—
Q4. スマートカード（ICカード社員証）または FIDO2 / Windows Hello for Business による認証が一部でも導入されているか
特定部署・管理者限定での導入でも△。全社展開済みなら○

Q5. 条件付きアクセス（Conditional Access）ポリシーが基本設定されているか（社外IP・未管理デバイスからのアクセス制御等）
Entra ID（Azure AD）P1 以上が必要。Microsoft 365 Defender とも連携可

🔵 60〜79
改善期（Managed）
基本的なID管理の仕組みは整備済みです。残存する課題（特定領域の低スコア項目）を計画的に対処することで、次のレベルに到達できます。IGA導入・PAM高度化・FIDO2移行計画の策定をお勧めします。
🟡 40〜59
要強化（Developing）
複数の重要課題が未対処の状態です。特に低スコアの領域（認証管理・特権管理等）を優先して対処してください。全社MFA展開・LAPS導入・SIEM連携は比較的短期間・低コストで実施可能な対策です。
🟠 20〜39
要緊急対応（Initial）
基本的なセキュリティ管理が不足しており、外部攻撃・内部不正による侵害リスクが高い状態です。管理者MFA適用・監査ログ有効化・休眠アカウント棚卸しを直ちに実施してください。経営層へのエスカレーションを推奨します。
🔴 0〜19
危機的状況（Ad-hoc）
ID管理の基盤が脆弱であり、ランサムウェア被害・情報漏洩・内部不正のリスクが極めて高い状態です。即座に経営層・CISO・情報セキュリティ委員会へ報告し、緊急対処計画を策定してください。外部のセキュリティ専門家（MSSP）への相談も検討してください。
スコアの留意点: このチェックリストは定性的な自己評価です。同じ○であっても実装品質は組織によって異なります。外部ペネトレーションテスト・セキュリティ診断サービスと組み合わせることでより正確な現状把握が可能です。

5. 棚卸しスクリプト集（PowerShell）

Active Directory の棚卸し・現状把握に利用できる PowerShell スクリプト集。ドメインコントローラー上またはAD管理ツールインストール済みのWindows端末で実行してください。
実行前の注意: これらのスクリプトはドメインに参加した Windows Server 上で、Domain Admins またはそれに相当する権限で実行してください。本番環境での実行前に必ずテスト環境での動作確認を行ってください。

5a. ADユーザー一覧取得（全ユーザー・無効アカウント含む）

全ADユーザーを CSV エクスポートします。棚卸しの基礎データとして活用してください。

# AD全ユーザー一覧（無効アカウント含む）
Import-Module ActiveDirectory
Get-ADUser -Filter * -Properties DisplayName,Enabled,LastLogonDate,PasswordLastSet,MemberOf |
    Select-Object SamAccountName,DisplayName,Enabled,LastLogonDate,PasswordLastSet |
    Export-Csv -Path ".d_users_$(Get-Date -Format yyyyMMdd).csv" -Encoding UTF8 -NoTypeInformation
Write-Host "エクスポート完了" -ForegroundColor Green

5b. 休眠アカウント検出（90日以上ログインなし）

90日以上ログインのない有効アカウントを検出します。棚卸し後の無効化対象リストとして活用してください。

# 90日以上ログインなし（有効アカウントのみ）
$threshold = (Get-Date).AddDays(-90)
Get-ADUser -Filter {Enabled -eq $true -and LastLogonDate -lt $threshold} `
    -Properties DisplayName,LastLogonDate,Department,Manager |
    Select-Object SamAccountName,DisplayName,LastLogonDate,Department |
    Sort-Object LastLogonDate |
    Export-Csv -Path ".\dormant_accounts_$(Get-Date -Format yyyyMMdd).csv" -Encoding UTF8 -NoTypeInformation
注意: LastLogonDate は DC ごとにレプリケーションに最大14日の遅延が生じることがあります。正確な検出には LastLogon を全DCで確認するか、LastLogonTimestamp（14日以内に同期）を使用してください。

5c. 特権グループのメンバー一覧

Domain Admins / Enterprise Admins / Schema Admins / Administrators グループのメンバーを一覧表示します。

# 特権グループのメンバー一覧
$privilegedGroups = @("Domain Admins","Enterprise Admins","Schema Admins","Administrators")
foreach ($group in $privilegedGroups) {
    Write-Host "=== $group ===" -ForegroundColor Yellow
    Get-ADGroupMember -Identity $group -Recursive |
        Where-Object {$_.objectClass -eq "user"} |
        Get-ADUser -Properties DisplayName,LastLogonDate |
        Select-Object SamAccountName,DisplayName,LastLogonDate
}

5d. サービスアカウント候補の検出

パスワード無期限かつユーザーによる変更不可に設定されているアカウントを抽出します。未管理のサービスアカウントを可視化します。

# サービスアカウント候補（パスワード無期限 かつ ユーザーによるパスワード変更不可）
Get-ADUser -Filter {PasswordNeverExpires -eq $true -and CannotChangePassword -eq $true} `
    -Properties DisplayName,PasswordLastSet,LastLogonDate,ServicePrincipalNames |
    Select-Object SamAccountName,DisplayName,PasswordLastSet,LastLogonDate,
        @{N='SPN数';E={$_.ServicePrincipalNames.Count}} |
    Export-Csv -Path ".\service_accounts.csv" -Encoding UTF8 -NoTypeInformation
推奨改善策: サービスアカウントは可能な限り gMSA（Group Managed Service Account） に移行してください。gMSA はパスワードが AD によって自動ローテーションされるため、パスワード管理の負担と漏洩リスクを大幅に低減できます。

5e. グループポリシーオブジェクト（GPO）一覧

全 GPO の一覧と最終更新日・リンク状況を確認します。未使用・長期未更新の GPO を特定できます。

# グループポリシーオブジェクト一覧（リンク先付き）
Import-Module GroupPolicy
Get-GPO -All | Select-Object DisplayName,GpoStatus,CreationTime,ModificationTime |
    Sort-Object ModificationTime -Descending |
    Export-Csv -Path ".\gpo_list.csv" -Encoding UTF8 -NoTypeInformation

# GPOリンク状況（ドメインルートの継承情報）
Get-GPInheritance -Target (Get-ADDomain).DistinguishedName |
    Select-Object -ExpandProperty GpoLinks |
    Select-Object DisplayName,Enabled,Enforced,Order

📌 追加で確認すべき PowerShell コマンド

パスワードポリシー確認:

Get-ADDefaultDomainPasswordPolicy

Fine-Grained Password Policy:

Get-ADFineGrainedPasswordPolicy -Filter *

監査ポリシー確認:

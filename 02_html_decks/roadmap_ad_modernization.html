📍 ADモダナイゼーション ロードマップ

Active Directory → Entra ID 移行の段階的実施計画 | 2026-04-07 | NSSol IDM参照資料

前提認識： ADは「一夜にして廃止」できません。多くの日本企業で3〜7年の移行期間が現実的です。 本ロードマップは「段階的リスク低減」を基本方針とし、ビジネス継続性を最優先します。

全体工程概要

Phase 10〜6ヶ月
診断・基盤整備
Phase 26〜18ヶ月
ハイブリッド移行
Phase 318〜36ヶ月
クラウドシフト
Phase 436ヶ月〜
AD縮小・廃止
1
診断・現状可視化・リスク評価
📅 目安: 0〜6ヶ月
🔍 AD健全性診断BloodHound/Pingcastle等でAD構造分析。SID History・GPO・Trust関係を棚卸し。
👥 アカウント棚卸し90日未使用・無期限PWD・ネストGrp等の特定。Tier 0/1/2の識別。
📋 アプリ依存調査AD認証依存アプリケーションの全数調査。NTLM依存（廃止困難）の特定。
⚠️ 2029年問題確認WS2019/MIM 2016のEOL（2029年）への対応計画策定。
🎯 目標状態定義最終的にADを完全廃止するか残すかの経営判断。
2
ハイブリッド構成・Entra ID Syncの確立
📅 目安: 6〜18ヶ月
🔗 Entra Connect Sync設定AD→Entra ID 同期設定。UPN整合性確認。PasswordHash Sync or Federation選択。
💻 Entra Hybrid Join展開Windows PCをHybrid Join化。条件付きアクセス(CA)の段階適用開始。
🛡️ MFA全社展開SSPR+Microsoft Authenticator全社展開。ADFSがある場合は縮小検討。
🔑 特権ID分離（Tier 0）Tier 0（DCアクセス可能）IDの特定と専用ワークステーション（PAW）整備。
📦 非M365アプリのSSO化SaaSアプリのEntra ID SAML/OIDC連携。Azure AD App Proxyでオンプレアプリ公開。
3
クラウドシフト・AD依存の系統的削減
📅 目安: 18〜36ヶ月
🏢 新PCはEntra Join（AD参加なし）新規購入PCはEntra Joinのみ。Intune MDMで管理。GPO代替をIntuneポリシーで実施。
🖥️ サーバーOS認証の移行LinuxはEntra ID SSHまたはLDAP over TLS。WindowsサーバーはEntra Hybrid Join検討。
🔐 PAM本格展開特権アカウントをPAM（CyberArk等）管理下に。管理者共有アカウント廃止。
📊 IGA導入プロビジョニング自動化。FISC/PCI等の棚卸自動化。SOD管理。
🌐 SASE/ゼロトラスト移行VPN廃止。SASE（Zscaler等）＋Entra ID CAでゼロトラストアクセス。
4
AD縮小・廃止（レガシー完全刷新）
📅 目安: 36ヶ月〜（企業規模による）
🏚️ ADドメイン縮小残留するADドメインを集約（10→2→1）。フォレストTrustを段階廃止。
🔧 NTLM完全廃止NTLM依存アプリの改修または廃止。Kerberos/OIDCへの切り替え完了。
🗑️ MIM廃止または後継へMIM 2016のEOL（2029年）前にIGA製品へ完全移行。
✅ AD廃止またはManagedドメイン化最終的にAD廃止 or Azure AD DS（Managed Domain）に縮小。

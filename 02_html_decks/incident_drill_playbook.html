🚨 ADアカウント侵害インシデント対応プレイブック

特権アカウント乗っ取り・AD侵害シナリオの初動対応手順と訓練ガイド

⚠️ このドキュメントは訓練・準備用です。実際のインシデント発生時は所定の緊急連絡先（CSIRT）に即時連絡してから本手順を実施してください。
🎯 侵害シナリオ概要（訓練シナリオ）
シナリオ侵害内容影響範囲
シナリオA（軽度）一般ユーザーのパスワード漏洩・不審ログイン当該ユーザーのみ
シナリオB（中度）サーバー管理者アカウントの侵害管理対象サーバー群
シナリオC（重度）ドメイン管理者（Domain Admin）の侵害AD全体・全サーバー
シナリオD（最重度）DCSync攻撃・Kerberoasting・Golden Ticket発行ドメイン全体（完全制圧）
⏱️ シナリオC：ドメイン管理者侵害 対応タイムライン
Phase 1: 検知・初動（0〜30分）
  1. SIEM/SentinelのアラートでDomain Admin権限の異常ログインを検知
  2. SOC担当者がCSIRTリーダーに即時エスカレーション
  3. 被疑アカウントの即時無効化（ADコンソール or PowerShell）
  4. 被疑端末のネットワーク隔離（VLAN切り替え or スイッチポート停止）
  5. 侵害発生の証拠保全開始（ログのバックアップ）
Phase 2: 封じ込め（30分〜2時間）
  1. 全Domain Adminアカウントのパスワード強制リセット（KRBTGT含む2回リセット）
  2. 侵害期間中に作成された新規アカウントの洗い出し・無効化
  3. 異常な権限昇格がないかAD全体を確認
  4. バックアップシステムが感染していないか確認
  5. 外部通信ブロック（C2サーバーへの通信遮断）
Phase 3: 根絶・復旧（2時間〜48時間）
  1. 侵害された端末のフォレンジック調査（マルウェア有無確認）
  2. マルウェア感染端末のクリーンインストール
  3. Golden Ticketが発行された可能性 → KRBTGTアカウントのパスワードを再度リセット
  4. 全ユーザーへの強制パスワードリセット通知
  5. Tiered AD管理モデルの緊急適用（Tier 0/1/2分離）
Phase 4: 事後対応・再発防止（48時間〜）
  1. インシデントレポート作成（経営層・規制当局向け）
  2. 侵害の根本原因分析（RCA）
  3. PAM導入・特権アカウント管理強化の計画策定
  4. 従業員向けフィッシング訓練の再実施
  5. 今後の監視強化（SIEM検知ルールの更新）
💻 初動対応コマンドリファレンス（PowerShell）

被疑アカウントの即時無効化

Disable-ADAccount -Identity "suspect_user" # または全Domain Adminを一覧表示して確認 Get-ADGroupMember -Identity "Domain Admins" | Select-Object Name, SamAccountName

KRBTGTパスワードリセット（2回実施）

Set-ADAccountPassword -Identity "krbtgt" -Reset -NewPassword (ConvertTo-SecureString "NewP@ss!2026" -AsPlainText -Force) # 最低10時間後に再度実施（チケット有効期限を超えるため）

最近作成されたアカウントの確認

$since = (Get-Date).AddDays(-7) Get-ADUser -Filter {WhenCreated -ge $since} | Select-Object Name, WhenCreated, Enabled

異常なグループメンバーシップの確認

$privileged = @("Domain Admins","Enterprise Admins","Schema Admins","Administrators") foreach ($grp in $privileged) { Write-Host "=== $grp ===" -ForegroundColor Cyan Get-ADGroupMember -Identity $grp | Select-Object Name, SamAccountName }

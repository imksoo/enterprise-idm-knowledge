📋 なぜID管理がセキュリティの核心か

「IDを制する者が企業インフラを制する」— すべての侵害はクレデンシャルから始まる

Verizon DBIR 2024によると、セキュリティ侵害の86%がクレデンシャル窃取を伴う。攻撃者はADドメイン管理者権限を1つ取れば、全社のファイルサーバー・メール・業務システム・バックアップに無制限アクセスできる。IDM（ID管理）の強化は、セキュリティ対策の中でも最も投資対効果が高い領域の一つだ。

🎯 AD が「攻撃の王冠」と呼ばれる理由

  • ドメイン管理者アカウント1つで全社インフラへのアクセスが可能
  • GPOを悪用すれば全端末にマルウェアを一斉展開できる
  • Kerberosチケットを偽造すればパスワードなしで認証突破できる
  • ADのバックアップ（ntds.dit）を取得すれば全ハッシュを一括抽出できる
  • NTLM認証を悪用すればパスワードを知らずに認証できる（Pass-the-Hash）

📊 日本企業のID管理の現実

  • 管理者アカウントが複数人で共有されているケースが多い
  • サービスアカウントのパスワードが数年間変更なし
  • 退職者のIDが30日以上有効なままの企業が半数超
  • 特権アカウントのMFA未導入率：中堅企業で60%超
  • AD監査ログがSIEMに転送されていない企業が多数

⚔️ 攻撃手法×被害×対策 — 6種の主要攻撃パターン

各攻撃パターンの手順・被害・技術対策・推奨製品・実装優先度を網羅

🔑 攻撃1: Pass-the-Hash / Pass-the-Ticket

影響範囲: 高 | 検知難易度: 中〜高 | 対策優先度: 緊急

⚡ 攻撃手順

  1. フィッシング等でエンドポイントへ侵入
  2. Mimikatz等のツールでLSASSプロセスからNTLMハッシュを抽出
  3. 取得したハッシュを使って認証（パスワード不要）
  4. 他サーバーへ横移動（RDP/SMB/WinRM）
  5. より高権限のハッシュを収集してDCへ到達

💥 被害範囲

  • パスワード変更前の全システムへの不正アクセス
  • 横移動によるネットワーク全域への拡散
  • DC到達後は全社の認証インフラ掌握

🛡️ 技術的対策

  • Windows Credential Guard（VBS）の有効化 → LSASSからのハッシュ抽出を困難化
  • NTLM認証の段階的無効化（まず監査→Kerberos優先→NTLM禁止）
  • Protected Usersグループへの管理者追加（NTLM/RC4禁止）
  • LSA Protection の有効化（RunAsPPL: 1）
  • 管理者アカウントの端末間共有禁止（ローカル管理者パスワードをLAPSで個別化）
  • SMB Signing 必須化（中間者攻撃防止）

🔧 推奨製品・設定

  • Microsoft LAPS（無償）: ローカル管理者パスワードの個別化・自動ローテーション
  • CyberArk EPM: エンドポイントでのMimikatz系ツール実行ブロック
  • Microsoft Defender for Identity: LSASS Dumpの異常検知

🎟️ 攻撃2: Kerberoasting / Golden Ticket攻撃

影響範囲: 非常に高 | 検知難易度: 高 | 対策優先度: 緊急

⚡ 攻撃手順（Kerberoasting）

  1. ドメインユーザー権限でSPNが設定されたサービスアカウントを列挙
  2. KerberosサービスチケットをKDCにリクエスト
  3. 取得したチケットをオフラインでブルートフォース
  4. 弱いパスワードのサービスアカウントのパスワードを解読
  5. サービスアカウントで高権限システムへアクセス

⚡ Golden Ticket攻撃

  1. DCSync攻撃またはntds.dit取得でkrbtgtアカウントハッシュを入手
  2. krbtgtハッシュを使って任意のKerberosチケットを偽造（Golden Ticket）
  3. 偽造チケットで任意ユーザーとして全ドメインリソースにアクセス
  4. 検知されてもkrbtgtパスワードをリセットするまで有効

🛡️ 技術的対策

  • サービスアカウントのパスワードを20文字以上のランダム文字列に変更
  • gMSA（グループ管理サービスアカウント）への移行（自動ローテーション）
  • Kerberos AES暗号化の強制（RC4-HMAC禁止）
  • krbtgtアカウントのパスワードを定期的に2回リセット（最低年2回）
  • DCSync権限を持つアカウントの最小化と監視
  • Defender for Identity でKerberoastingの異常検知

🔧 推奨製品

  • Microsoft Entra ID / AD: gMSAによるSPN管理
  • CyberArk PAM: サービスアカウントのボールト管理・自動ローテーション
  • Defender for Identity: Kerberoasting・DCSync異常検知

💥 攻撃3: ランサムウェア（AD管理者乗っ取り→全社暗号化）

影響範囲: 全社 | 被害額: 数億〜数十億円 | 対策優先度: 最緊急

⚡ 攻撃手順

  1. フィッシングメール・VPN脆弱性・RDPブルートフォースで初期侵入
  2. 1〜2週間かけてネットワーク内を静かに偵察・横移動
  3. ドメイン管理者権限を取得（Kerberoasting・Pass-the-Hash等）
  4. バックアップシステムを特定・削除または暗号化
  5. GPOを使って全端末・サーバーにランサムウェアを一斉展開
  6. 暗号化実行→脅迫メッセージ表示→身代金要求

💥 被害範囲・影響

  • 全社システム停止（平均復旧期間: 3〜4週間）
  • 身代金要求: 数千万〜数億円
  • 復旧費用（システム再構築含む）: 数億〜数十億円
  • 事業機会損失・レピュテーション損傷

🛡️ 技術的対策

  • Tiered Admin Model: ドメイン管理者をDC専用機からのみ使用可能に制限
  • LAPS: ローカル管理者パスワードを個別化して横移動を阻止
  • ネットワークセグメンテーション: サーバー・端末間のSMB通信制限
  • バックアップの隔離: 3-2-1ルール＋オフライン/不変ストレージ
  • EDR（Defender for Endpoint等）でのプロセス監視
  • GPO悪用の検知: 不審なGPO変更をアラート

🔧 推奨製品

  • Microsoft LAPS / Entra LAPS: ローカル管理者パスワード管理（無償）
  • CyberArk PAM / Delinea Server PAM: 特権アクセス制御
  • Defender for Identity: ADへの異常アクセス検知
  • Microsoft Sentinel: SIEM・SOC統合

📱 攻撃4: フィッシング → MFA疲労攻撃 → セッションハイジャック

影響範囲: 中〜高 | 近年急増 | 対策優先度: 高

⚡ 攻撃手順

  1. フィッシングサイトでメール・パスワードを窃取（AiTM: Adversary-in-the-Middle）
  2. 取得した資格情報でログイン試行 → MFAプッシュ通知が対象者に送信される
  3. 深夜や繰り返しプッシュ通知を送り続けて「承認疲れ」を狙う
  4. 対象者が誤って承認 → 攻撃者がセッションCookieを取得
  5. セッションCookieでMFAをバイパスしてメール・SharePointにアクセス

🛡️ 技術的対策

  • プッシュ通知の「番号照合（Number Matching）」を必須化
  • FIDO2/パスキーへの移行（フィッシング耐性あり）
  • 条件付きアクセス: 登録済みデバイスからのみ許可
  • UEBA（異常認証検知）によるAiTM検知
  • 継続的アクセス評価（CAE）でセッションCookie窃取を無効化

🔧 推奨製品

  • Entra ID P2: Number Matching、CAE、サインインリスク検知
  • FIDO2 セキュリティキー: YubiKey等（フィッシング完全耐性）
  • Microsoft Sentinel / Defender XDR: AiTM攻撃の検知

⚙️ 攻撃5: サービスアカウント悪用（権限過剰・パスワード不変）

影響範囲: 中〜高 | 発見難易度: 高（長期潜伏） | 対策優先度: 高

⚡ 攻撃手順

  1. Kerberoasting等でサービスアカウントのパスワードを解読
  2. サービスアカウントの権限（多くはDomain Adminsに過剰付与）で横移動
  3. サービスアカウントは通常ログを監視されないため長期潜伏可能
  4. 業務システムの設定ファイルにパスワードがハードコードされている場合も悪用

🛡️ 技術的対策

  • gMSA（グループ管理サービスアカウント）への移行: パスワード自動ローテーション
  • サービスアカウントの最小権限化: 必要なリソースにのみアクセス許可
  • PAMボールトへの格納: CyberArk/Delineaでパスワード管理・自動更新
  • 設定ファイルのパスワードハードコード禁止: Secrets Manager移行
  • サービスアカウントへの不審なログイン監視

🔧 推奨製品

  • CyberArk/Delinea: サービスアカウントボールト・自動ローテーション
  • Microsoft gMSA: AD標準機能（無償）
  • HashiCorp Vault / Azure Key Vault: アプリのシークレット管理

👤 攻撃6: 内部不正・退職者残留アカウント

影響範囲: 中〜高 | 発見難易度: 非常に高 | 対策優先度: 高

⚡ リスクシナリオ

  1. 退職者のIDが30日以上有効のままクラウドシステムにアクセス可能
  2. 異動後も前部署の権限が残ったまま（権限の累積）
  3. 不満を持つ現職員が退職前に機密データを外部転送
  4. 委託先SE離任後もVPN/クラウドアクセスが残留
  5. 共有アカウントのため誰が操作したか特定不可能

🛡️ 技術的対策

  • IGAによる退職処理の自動化: 人事システム連携でDay0無効化
  • 権限レビュー（アクセス認定）の定期実施: 四半期ごとに棚卸し
  • UEBA（異常行動分析）: 深夜アクセス・大量ダウンロードの検知
  • JIT（Just-in-Time）権限: 常時付与ではなく必要時のみ付与
  • DLP（データ損失防止）: 機密データの外部転送をブロック

🔧 推奨製品

  • SailPoint / Entra ID Governance: IGA・アクセス認定の自動化
  • Microsoft Purview / Defender for Cloud Apps: UEBA・DLP
  • Entra ID P2: アクセスレビュー機能

⏱️ インシデント発生時の初動対応タイムライン

「何をいつやるか」の優先順位が被害の最小化を決める

0〜1時間: 検知・封じ込め
最優先アクション:
1. 侵害端末のネットワーク隔離（NICの無効化またはVLAN切り離し）
2. インシデントレスポンスチームの召集（CISO・情シス・法務・経営）
3. 影響範囲の初期判断（どのシステムが侵害されたか）
4. ドメイン管理者アカウントのパスワード即時変更（疑い段階でも実施）
1〜6時間: 範囲特定・証拠保全
調査アクション:
1. ADの監査ログ・イベントログの保全（書き換え防止のためエクスポート）
2. Mimikatz実行痕跡・新規管理者アカウント追加の確認
3. 攻撃者がアクセスしたシステム・データの特定
4. バックアップの完全性確認（ランサムウェア展開前のバックアップは残っているか）
6〜24時間: 封じ込め・初期復旧
復旧アクション:
1. krbtgtアカウントのパスワードを2回リセット（Golden Ticket無効化）
2. 侵害済みアカウントの全セッション強制切断・パスワード変更
3. 侵害端末の完全クリーンアップ（イメージ再展開）
4. バックアップからの重要システム復旧順序の決定
1〜7日: 全社復旧・再発防止
恒久対策アクション:
1. セキュリティベースラインの再適用（LAPS・Credential Guard・SMB Signing）
2. 全ユーザーのパスワード強制変更
3. MFAが未設定のアカウントへの緊急展開
4. インシデント報告書の作成（必要に応じて個人情報保護委員会への報告）

💼 NSSOLとして提案できるソリューション体系

緊急→短期→中期の3フェーズで体系的に防御を構築

🚨 緊急対策（〜1ヶ月）: 今すぐできるリスク低減

緊急
LAPS（ローカル管理者パスワード管理）導入
全端末のローカルAdministratorパスワードを個別化・自動ローテーション。横移動の最も効果的な阻止策。実装工数: 2〜4週間、費用: 無償（Entra LAPS）
緊急
特権ID棚卸し・管理者MFA必須化
ドメイン管理者・Enterprise Adminsの洗い出しと人数削減。全特権アカウントへのMFA適用。実装工数: 1〜2週間
緊急
AD監査ログの有効化とSIEM転送
主要なADイベント（ログオン失敗・特権操作・グループ変更）のログを有効化してSentinel/SIEMに転送。実装工数: 1〜2週間

⚡ 短期対策（〜3ヶ月）: セキュリティ基盤の構築

短期
MFA全社展開（Entra MFA / Okta）
全従業員へのMFA展開。Microsoft Authenticatorプッシュ通知からFIDO2への段階移行。概算費用: Entra P1 約1,000円/人/月
短期
PAM基盤構築（CyberArk/Delinea）
特権アカウントのボールト管理・セッション録画・自動パスワードローテーション。概算費用: 1,000名規模で年間2,000〜5,000万円
短期
Credential Guard / SMB Signing 全展開
Intune/GPOでCredential Guard（VBS）とSMB Signingを全端末に適用。Pass-the-Hash攻撃の大幅阻止。実装工数: 4〜8週間

📅 中期対策（〜1年）: ゼロトラスト・IGA体制確立

中期
IGA導入（SailPoint/Entra Governance）
IDライフサイクルの自動化・権限レビュー・シャドーIT可視化。退職者ID自動無効化で残留アカウントリスクを解消。
中期
ゼロトラスト移行（Entra条件付きアクセス＋Intune）
デバイスコンプライアンス確認・リスクベース認証・マイクロセグメンテーションによるゼロトラスト体制構築。
中期
Defender for Identity / Sentinel SOC構築
ADへの攻撃をリアルタイム検知するSOC体制。Sentinel SIEM＋Defender XDRでの統合セキュリティ監視。

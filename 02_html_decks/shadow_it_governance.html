🕵️ シャドーIT対策・SaaS統制ガイド

DX部門の「勝手SaaS」を禁止ではなく管理へ ― IT部門とDX部門の共存策

シャドーITとは何か、なぜ問題か

シャドーITとは、IT部門の承認・管理を受けずに現場部門が独自に導入したシステム・SaaSのことです。

シャドーITの危険：IT部門が知らないシステムにはセキュリティ設定が適切でない場合が多く、退職者のIDが止まらない・パスワードが共有されるといった問題が発生します。情報漏洩が起きても検知できない。
日本企業の現実：コロナ禍でTeams・ZoomなどSaaSの採用が爆発的に増加。多くの企業でIT部門が追いつかず、現場が勝手に導入したSaaSが何十個もある状態です。

3つのアプローチの比較

❌ 禁止・遮断

承認されていないSaaSへのアクセスをネットワークでブロック

結果：DX部門が反発。VPNで迂回。信頼を失う。DXが止まる。

⚠️ 黙認・事後対応

現場のSaaS導入を黙認して問題が起きたら対応

結果：問題が大きくなってから発覚。インシデント対応コストが高くなる。

✅ ファストトラック承認

低リスクSaaSを2週間以内に承認。SSO設定を条件にする。

結果：現場のスピードを維持しつつIT部門が統制。Win-Winの解決策。

ファストトラック承認制度の設計

承認フロー（目標：申請から2週間以内に決定）

  1. 現場部門が申請：SaaS名・用途・利用人数・費用をフォームで提出
  2. IT部門がリスク評価：セキュリティ評価（SOC2認証有無・SAML/SSO対応・データ保存場所）
  3. 承認 or 条件付き承認 or 却下：2週間以内に回答
  4. 承認条件：
    • 会社のIdP（Entra ID / Google Workspace）のSSOを設定すること
    • 管理者アカウントはIT部門も持つこと
    • 退職者ID停止手順を確立すること

リスク分類（迅速判断のための基準）

分類条件承認方針
低リスク（ファストトラック）SOC2 Type II認証あり・SSO対応・データ保存が国内または同意済みリージョン2週間以内に原則承認
中リスク（要検討）上記の一部が不明または未対応追加確認後、1ヶ月以内に承認可否
高リスク（原則不可）個人情報・機密情報を扱う・海外不明事業者・セキュリティ認証なし代替SaaSを提案して却下

既存シャドーITの棚卸し方法

すでに社内に入り込んでいるシャドーITを把握するには：

  1. 社内アンケート：各部門に「使っているクラウドサービスを全部教えてください」のアンケートを実施（匿名可）
  2. プロキシ・ファイアウォールログ解析：社内ネットワークからアクセスされているドメインを一覧化
  3. CASB（クラウドアクセスセキュリティブローカー）の活用：Microsoft Defender for Cloud Apps等でSaaS利用状況を自動可視化
推奨アクション：まずアンケートで現状を把握し、重大リスクのあるSaaS（個人情報・機密情報を扱うもの）を優先的に対処します。全件を一度に解決しようとせず、重大なもの3〜5件から始めてください。
